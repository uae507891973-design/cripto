# Поэтапный план создания спот-торгового бота для Bybit

> Статус: план (v1). Технические условия интеграции проверены по официальной
> документации Bybit V5 API (июль 2026). Пункты, помеченные ⚠, нужно
> перепроверить в личном кабинете Bybit на момент реализации — биржа меняет
> правила.

---

## Этап 0. Постановка задачи и выбор пути (1–3 дня)

**Результат этапа:** зафиксированная стратегия, границы риска и выбранный стек.

1. Определить стратегию: grid (сетка), DCA (усреднение), моментум/трендовая,
   маркет-мейкинг. От этого зависит весь стек:
   - **Без кода** — нативные боты Bybit (Spot Grid / Spot DCA): не нужен сервер
     и передача ключей, но только шаблонные стратегии.
   - **Своя логика** — Freqtrade (Python, официальная поддержка Bybit spot,
     бэктест, dry-run) или собственный бот на официальном SDK `pybit`.
   - **Маркет-мейкинг/HFT** — Hummingbot (коннектор `bybit`).
2. Зафиксировать риск-параметры письменно: торговые пары, максимальный капитал
   бота, максимальный размер позиции, дневной лимит убытка (после которого бот
   останавливается), максимальное число открытых ордеров.
3. Юрисдикция: убедиться, что Bybit доступен и легален в вашей стране;
   учесть налоговый учёт сделок. ⚠ Для Нидерландов и Гонконга Bybit требует
   отдельные API-домены (`api.bybit.nl`, `api.bybit.com.hk`).

## Этап 1. Условия интеграции с Bybit (проверено по докам V5)

**Результат этапа:** рабочий аккаунт, ключи и понимание всех ограничений биржи.

### 1.1. Аккаунт
- Нужен **Unified Trading Account (UTA)** или Classic-аккаунт. Легаси Unified
  Margin Account **не может торговать спот через V5 API** — Bybit прямо
  рекомендует апгрейд до UTA (`/v5/account/upgrade-to-uta`).
- ⚠ Пройти KYC-верификацию до создания API-ключей — без неё действуют
  ограничения на торговлю и вывод.
- Рекомендуется завести **отдельный субаккаунт** под бота и держать на нём
  только рабочий капитал (изоляция ущерба при компрометации ключа).

### 1.2. API-ключи: два типа
| Тип | Криптография | Где хранится секрет |
|---|---|---|
| System-generated | HMAC-SHA256 | пара ключей выдаётся биржей — секрет знает и Bybit |
| Self-generated | RSA-SHA256 | приватный ключ генерируете вы (`api-rsa-generator`), Bybit получает **только публичный** |

Для продакшена предпочтителен **RSA** — приватный ключ никогда не покидает ваш
сервер. ⚠ Ключи без привязки к IP у Bybit имеют ограниченный срок действия
(исторически ~3 месяца) — при создании ключа проверить актуальное правило и
сразу настроить IP-whitelist.

### 1.3. Аутентификация запросов (обязательные заголовки)
- `X-BAPI-API-KEY`, `X-BAPI-TIMESTAMP` (UTC, мс), `X-BAPI-SIGN`,
  `X-BAPI-RECV-WINDOW` (по умолчанию 5000 мс, защита от replay-атак).
- Подпись: `HMAC_SHA256`/`RSA_SHA256` от строки
  `timestamp + api_key + recv_window + queryString|body`.
- Жёсткое правило времени: `server_time − recv_window ≤ timestamp < server_time + 1000`.
  **Следствие:** серверу бота обязательна синхронизация NTP + периодическая
  сверка с `/v5/market/time`.
- `X-Referer` — только для участников брокерской программы Bybit (если бот
  делается как продукт для третьих лиц, вступать в Broker Program).

### 1.4. Окружения
| Окружение | REST | WebSocket | Особенности |
|---|---|---|---|
| Testnet | `api-testnet.bybit.com` | `stream-testnet...` | отдельная регистрация на testnet.bybit.com |
| Demo Trading | `api-demo.bybit.com` | `wss://stream-demo.bybit.com` | отдельный demo-UID внутри mainnet-аккаунта; ордера хранятся 7 дней; лимиты не повышаемые; batch-эндпоинты для спота недоступны |
| Mainnet | `api.bybit.com`, `api.bytick.com` | `stream.bybit.com` | NL: `api.bybit.nl`, HK: `api.bybit.com.hk` |

### 1.5. Rate limits (за нарушение — бан)
- **600 запросов / 5 с на IP**; превышение → `403` и автоматический бан ~10 минут.
- Per-UID (окно 1 с), спот: создание ордера **20/с**, отмена **20/с**,
  изменение **10/с** — повышаемые по запросу; query-эндпоинты ~10/с —
  **не повышаются** (для данных использовать WebSocket, не REST-поллинг).
- Batch-эндпоинты (`/v5/order/create-batch` и др.): 1–10 ордеров/запрос,
  лимит расходуется по числу ордеров; частичное превышение → часть пакета
  исполняется, остальное отклоняется с `retCode 10006`.
- WebSocket: ≤500 подключений за 5 минут, ≤1000 соединений на IP.
- Контроль остатка — заголовки `X-Bapi-Limit`, `X-Bapi-Limit-Status`,
  `X-Bapi-Limit-Reset-Timestamp`.

### 1.6. Официальные инструменты и поддержка
- SDK: **pybit** (Python, официальный), Go, Java, .NET; community Node.js
  (`bybit-api`).
- Примеры: `bybit-exchange/api-usage-examples`, Postman-коллекция
  `QuickStartWithPostman`.
- Каналы поддержки: Telegram `@BybitAPI`, Discord Bybit API.

## Этап 2. Архитектура бота (3–7 дней проектирования)

**Результат этапа:** схема модулей и контракты между ними.

```
[WS public spot] ─→ Market Data ─→ Strategy ─→ Risk Manager ─→ Execution (REST)
                                        ↑                          │
[WS private] ──→ Order/Fill Tracker ────┘          State Store ←───┘
                                                   (SQLite/Postgres)
Monitoring / Alerts / Kill-switch — поверх всех модулей
```

Ключевые решения:
1. **Данные** — только WebSocket (`wss://stream.bybit.com/v5/public/spot`,
   orderbook depth 1/50), REST — для восстановления состояния.
2. **Исполнение** — `POST /v5/order/create` с `category=spot`; каждому ордеру
   свой `orderLinkId` (идемпотентность: повтор запроса не создаст дубль).
3. **Учёт исполнений** — приватный WS (`wss://stream.bybit.com/v5/private`:
   order, execution, wallet) + периодическая сверка (reconciliation) через
   `/v5/order/realtime` и `/v5/account/wallet-balance`.
4. **Устойчивость** — обработка `retCode`, экспоненциальный retry, локальный
   rate-limiter с запасом от лимитов биржи, автопереподключение WS с
   восстановлением состояния, персистентный стейт (перезапуск без потери
   открытых ордеров).

## Этап 3. Безопасность (сквозной этап, закладывается до кода)

**Результат этапа:** чек-лист безопасности выполнен полностью.

### Ключи
- [ ] Права ключа — **минимальные**: только Read + Spot Trade.
      **Никогда не включать Withdrawal / Transfer.**
- [ ] IP-whitelist на статический IP сервера бота.
- [ ] RSA-ключи вместо HMAC; приватный ключ — только на сервере бота.
- [ ] Секреты — в переменных окружения / секрет-менеджере (Vault, SOPS,
      Docker secrets). **В git, логи и конфиги в репозитории — никогда**;
      добавить pre-commit секрет-сканер (gitleaks).
- [ ] Ротация ключей по расписанию (например, раз в квартал) и немедленно —
      при любом подозрении.
- [ ] Отдельный субаккаунт с ограниченным балансом; основной капитал — вне
      досягаемости ключа бота.

### Инфраструктура
- [ ] Выделенный VPS: вход только по SSH-ключам, firewall (открыт только SSH),
      автообновления безопасности, 2FA на аккаунте хостинга и на Bybit.
- [ ] Уменьшенный `recv_window` (меньше окно — меньше поверхность replay).
- [ ] NTP-синхронизация времени (иначе биржа отклонит подписи).
- [ ] Ключи и подписи не попадают в логи; логи — с ротацией.

### Операционная защита
- [ ] **Kill-switch**: одна команда/кнопка → `POST /v5/order/cancel-all`
      (category=spot) + остановка процесса.
- [ ] Автостоп по дневному убытку и по числу ошибок API подряд.
- [ ] Мониторинг: heartbeat бота, алерты (Telegram/e-mail) на: рассинхрон
      состояния, приближение к rate limit, аномальный размер позиции, разрыв WS.
- [ ] Третьим сервисам (облачные платформы) ключи не передавать; если
      передаёте — только read+trade, отдельный субаккаунт.

## Этап 4. Разработка и тестирование (2–6 недель)

**Результат этапа:** стратегия с положительным бэктестом, прогнанная на
демо-среде без расхождений учёта.

1. **Бэктест** на исторических данных (`/v5/market/kline`); учитывать комиссии
   и проскальзывание. ⚠ Актуальные спот-комиссии maker/taker смотреть в
   аккаунте Bybit — они зависят от VIP-уровня и в открытых верифицированных
   источниках не зафиксированы.
2. **Unit/интеграционные тесты**: подпись запросов, обработка `retCode`,
   реконнект WS, идемпотентность `orderLinkId`.
3. **Demo Trading / Testnet**: полный цикл стратегии минимум 2–4 недели.
   Помнить об отличиях demo: ордера живут 7 дней, лимиты дефолтные, спотовые
   batch-эндпоинты недоступны.
4. **Проверка сверки**: баланс и ордера по данным бота = данным биржи после
   суток работы, перезапуска процесса и обрыва сети.

## Этап 5. Запуск в прод (постепенно)

1. Canary-запуск с минимальным капиталом (например, 1–5% целевого) ≥2 недели.
2. Масштабирование капитала ступенями только при совпадении метрик с бэктестом.
3. Эксплуатация: журнал всех сделок (для налогов и анализа), еженедельная
   сверка PnL, ежемесячный пересмотр параметров стратегии, дежурный доступ к
   kill-switch с телефона.
4. План отката: остановка бота → cancel-all → ручное закрытие остатков.

## Этап 6. Соответствие правилам биржи (compliance)

- **KYC и региональные правила**: торговать только из разрешённой юрисдикции,
  использовать региональный API-домен, если предписан (NL/HK).
- **Запрещённые практики** по ToS Bybit: wash trading (сделки с самим собой),
  spoofing/layering (ордера без намерения исполнить), манипулирование ценой,
  злоупотребление API. Grid/DCA/MM-стратегии легальны, но self-match у
  маркет-мейкинга нужно исключать на уровне логики.
- **Rate limits — часть ToS**: систематические 403-баны могут привести к
  ограничениям аккаунта; закладывать клиентский лимитер с запасом ~20%.
- Повышенные лимиты и институциональные условия — через официальную программу
  Bybit (запрос повышения лимитов доступен из личного кабинета / через API
  Support).
- Если бот предоставляется третьим лицам — это уже брокерская деятельность:
  Broker Program Bybit (заголовок `X-Referer`) и, вероятно, лицензионные
  требования вашей юрисдикции.
